# Trackie Assistant 1.6.2rc2 — Linux preview

Save cloud music locally (currently Suno), then use your player of choice, such as Music Assistant.

## Changes since rc1

- Explicitly approved playlist retries can be restricted to an exact set of missing clip IDs. A changed inventory stops before transfers.
- Reviewed offline artist corrections now preserve one supported embedded JPEG or PNG cover in tail-moov M4A/MP4 files. Audio, cover bytes and unrelated metadata remain unchanged.
- Recovery tests cover interruption around artist publication. Extra audio streams, real video, multiple covers, mismatched images and chapters remain unsupported.
- Local browser acceptance can use an existing Chrome installation; CI continues to require Chromium.

## Installation and limits

Use the Python 3.13+ wheel with the CLI or WebUI, or the AMD64 Home Assistant add-on. Images and source/package checksums are attached when their checks finish.

This remains a Linux preview. Windows archive writes remain disabled; Windows recovery is roadmap work.

Updating the package does not automatically rename or retag existing recordings. An existing-library migration requires verified own-clip producer identities, independent review of its exact plan, and all library writers stopped throughout application and recovery. See [the migration guide](https://github.com/matthewhand/trackie-assistant/blob/v1.6.2rc2/docs/producer-migration.md).

Video downloads stay off by default. Temporary MP4 audio fallback discards the source video after verified extraction. Existing recordings are reused by clip identity.
